# 2026-10-10

## 表达式求值器加 math 函数（`53c1c40` 之后）

起因是上一条结论的遗留缺口：`when` 节点的 `expr` 只能写布尔比较，**连加减乘除都没有**，更没有随机数。世界包作者算不出「血量百分比」这类量。

用户拍板：**加在表达式求值器**（不是只加在图形节点绑定里），**随机数每次求值重掷**（不做同帧缓存）。

### 改了什么

`frontend/src/gameUiRuntime/expression.ts`：
- 新增算术运算：优先级 `||` → `&&` → 比较 → 加减 → 乘除模 → 一元负号。`/` 除零得 `Infinity`、`%` 除零得 `NaN`，不抛错。`+` 遇字符串走拼接（与 JS 一致）。
- 词法器加逗号 token 与算术运算符。
- 加函数调用解析：标识符后紧跟 `(` 时走白名单查表，非白名单直接抛错。
- 10 个函数：`math_min` / `math_max` / `math_abs` / `math_floor` / `math_ceil` / `math_round` / `math_clamp` / `math_lerp` / `math_random` / `math_random_int`。
- 函数表类型用 `Record<string, (...args: number[]) => unknown>` 而非 `as const` 对象——后者在分派处spread 会报 TS2556（union of tuple types 不能 spread）。

`src-tauri/src/services/game_ui/mod.rs` 的 `validate_expression`：
- **原来无条件禁止任何函数调用**（`function_like` 正则命中即报 `unsafe_expression`）。改成：仍然禁函数调用，但只允许 `EXPRESSION_FUNCTION_IDS` 这 10 个名字，白名单外的报新错误码 `unknown_expression_function`。
- 反引号 / 方括号 / 花括号 / 分号 / 问号仍然报 `unsafe_expression`。

### 关键约定（改函数时务必同步）

**前后端各有一份函数白名单，必须同步维护**：
- 前端 `expression.ts` 的 `GAME_UI_EXPRESSION_FUNCTIONS`（真正执行）
- 后端 `mod.rs` 的 `EXPRESSION_FUNCTION_IDS`（导入时提前报错）

后端先拦的好处是作者拿到明确错误码，而不是等运行时才失败。

### 随机数语义的坑（已写进文档）

每次求值重掷 ⇒ **同一帧内多处读同一个 `math_random()` 会得到不同值**。适合概率判定/抽格子，不适合需要帧内稳定的视觉量。后者要算好写进 `set_state` 再用 `$state.key` 读。

测试：后端 250 / 前端 83 全通过；新增后端 3 个 + 前端 16 个。

## 约定备忘

- **用户说「math 里没有随机数」指的是表达式求值器**（`when` 的 `expr`），不是 `logic.js`——后者本来就能用完整的 `Math`。
- 加新表达式能力时，先问清加在哪一层：表达式求值器影响所有 `when` 节点，图形节点绑定只影响新节点。
## 世界包卡牌对战可行性调研
- 通读 docs/world-package-guide-v3.md、docs/world-package-rpg-cookbook.md、examples/world-packages/（healthy-life 的 logic.js 与 world.json）。
- 结论：玩家 vs AI 回合制卡牌对战可行。推荐架构：规则结算与启发式 AI 全放 logic.js（无状态 Worker + session KV 存牌局，result_state 只回传玩家可见视图实现隐藏信息），世界主控仅做叙事氛围（可选）。

## 卡牌对战选型：确定大模型驱动 AI
- 用户拍板：不要启发式 AI，AI 对手必须由大模型驱动，模型输出结构要极简、重点在思考。
- 选型结论：首推「单挑德州扑克（简化版）」，MVP 用库恩扑克（每人 1 张 J/Q/K、各 1 筹码、一轮下注）验证链路；次选炉石 lite（每回合限出 1 张牌 + 单目标）。
- 拟定回路：动作按钮 → submit_message（动作即消息）→ 主控读 runtime_attributes（AI 底牌/公共牌/筹码/下注历史，玩家底牌只存 KV 不进属性）→ 输出极简 ai_action 字段（含台词）→ turn_completed 由 logic.js 校验合法性并权威结算，非法动作兜底跟注。

## 卡牌对战选型最终改为「恶魔轮盘」（Buckshot Roulette 玩法）
- 用户提出恶魔轮盘，评估后定为一期方案（优于德州）：模型输出无金额只有动作单字段（shoot_self / use_item+item+say）；状态为几个小整数（实/空弹计数、血量、道具、行动方）；弹匣顺序存 KV 不进属性实现信息对称；恶魔荷官角色由世界主控扮演。
- 关键设计：AI 连续行动（空包打自己后继续）用"一次开枪一拍"解决——主控每次回合带 choice 交互，玩家点击触发下一次主控回合，行动权状态机在 logic.js，非法动作兜底对对手开枪。
- 一期道具：放大镜（偷看当前弹）、饮料（退膛）、手铐（跳过对手行动）、刀（下一枪伤害翻倍），全部进属性双方可见。
- 实施路径：最小骨架（1 血、2 实 1 空、无道具）跑通主控回路 → 加血量/装填/道具。德州降级为二期备选。

## 修复 poison-feast 世界包导入失败：UI direction 取值非法
- 现象：导入报「世界 UI 包无效」+ 12 条 invalid_direction（堆栈只显示前 12 条，掩盖了真实原因）。
- 根因：UI 文档里 stack 的 direction 写成 CSS 语义 "row"，而 game-ui 校验器只接受 "horizontal" / "vertical"。desktop 14 处、mobile 11 处。
- 修复：全部替换为 "horizontal"，重新打包 ZIP。
- 验证方式（可复用）：在 src-tauri 里临时挂一个 #[cfg(test)] 测试直接调 WorldPackageService::import_package_archive 读 output/*.zip，打印真实 Err；跑通后删除临时文件并还原 mod.rs。cargo test --lib 全量 251 passed。
- 教训：world UI 文档的 schema 枚举值要对着 src-tauri/src/services/game_ui/mod.rs 的 match 分支核对（如 direction/ 节点 type 白名单），不能凭 CSS 直觉写。

## poison-feast 视觉升级：CSS 造物 → 真实生成插画
- 用户反馈"图片呢，怎么全变成代码绘制了"。原来试管/命烛全是 CSS 画的伪物质感，现改为真实生成的插画。
- 素材生成（ImageGen，共 5 次调用）：毒药试管、清水试管、4宫格（空管+燃烛+熄烛+恶魔头）、4宫格道具（银针+香炉+酒壶+倒水杯）、酒馆背景。可爱手绘风、粗描边。
- 关键机制考据（决定方案）：① game_ui 的 image 节点 src 直接进 `<img src>`，**不走资源重映射**，所以图片必须内嵌；② CSP 允许 `img-src data:`（tauri.conf.json 与 worldFrame/frameDocument.ts 的 iframe CSP 都放行 data:）；③ logic.js 无法写资源，只能写 KV。故选**CSS background-image + data URI 内嵌**（CSS 限额 1MB，比塞进 UI JSON 更合适）。
- 背景图例外：走 world.json 的 `ui_assets_config.local_background_assets` + manifest.assets 声明，宿主导入时落盘并生成 asset_map（实测重映射为 /assets/bg_tavern-<hash>.jpg），由宿主注入 --game-runtime-bg-image。
- 切图脚本要点：四宫格按 W//2/H//2 切；去白底用「亮度→alpha 遮罩 + ImageChops.darker」；形态学开运算去噪点；裁边必须在二值化 alpha 上做 getbbox，否则残留噪点会把 bbox撑满导致图像被压扁。输出 WebP q82 比 PNG 省一半（280KB→105KB）。
- UI JSON 改动：试管状态从「嵌套 liquid 层」改为按 kind 直接切类名（pf-tube-poison/water/spent），条件表达式用 `tube.status == 0 && tube.kind == poison`；新增 pf-devil-avatar 头像节点；道具卡片加 pf-item-icon + `pf-item-icon-{{ item.id }}` 动态类名。
-踩坑：Read 工具预览细高图时会显示成横条，误以为切图压扁了——实际像素尺寸正确，以后验证图片要拼接对比图而不是只看单个文件。
- 背景图生成图带「AI生成」水印（右下角）+ 强暗角，必须裁掉并提亮降饱和再用。
- 验证：真实导入校验器通过（ui_runtime=3, caps=[supports_world_storage], asset_map 正确重映射），cargo test --lib 251 全过。
