## 小恶魔的毒酒宴世界包：UI 线上空白事故复盘与修复

用户导入世界包后整块牌桌不渲染（截图里只剩「第__轮」「架上__支」两个空值徽章）。
根因不是样式，而是**对宿主 UI DSL 绑定语义的误解**，且上一轮"浏览器验证"方法本身是错的。

### 五个根因

1. **状态绑定路径全错（致命）**
   宿主 `resolvePath` 先查 `state` / `data` / `locals`，裸键 `view.round` 会落到
   `runtimeData.view`（不存在）→ 所有插值变空串、所有 `when` 条件为假 → 牌桌整块不渲染。
   正确写法：`state.view.round`。
   参考实现：`examples/world-packages/healthy-life/world/ui.desktop.jsonc`。

2. **`for_each` 不能带布局属性**
   `GameUiRenderer.renderLoopNode` 返回 Fragment，**不产生任何 DOM 包装元素**，
   写在 `for_each` 上的 `class_name` / `direction` / `gap` 全部被静默丢弃。
   要横向排列必须在 `for_each` 外面套一层 `stack`。

3. **`when` 的 `class_name` 同样无效**（直接返回 child，不加包装）。

4. **缺根高度链**
   世界包 CSS 必须写 `html, body, #root, .game-root, .game-ui-layout { height: 100% }`，
   否则布局塌成内容高度、背景图从下方漏出。参考 `accounting-assistant/world/ui.desktop.css`。

5. **`when` 分支重叠导致一格画两支试管**
   catch-all 的 `status == 0` 与 `status == 0 && kind == 'poison'` 同时命中，
   4 个试管格子渲染出 6 支试管。三分支必须写成互斥的 kind 枚举。

### 验证方法教训（最重要）

上一轮用**自造的原型 HTML** 验证，全部通过，但那是自己实现的渲染逻辑，
和宿主 `GameUiRenderer` 的绑定语义完全不同 → 测试全绿、线上空白。
现在改为三层真实验证：

- `frontend/src/test-utils/worldUiProbe.ts`：用真实 `GameUiRenderer` + `evaluateGameUiExpression`
  经 `renderToStaticMarkup` 产出 HTML 断言。
  注意：state 必须**深合并**进 `document.state`（renderer 用它做 useState 初值）。
- `frontend/src/test-utils/poisonFeastLogicHarness.ts`：用真实 logic.js + 宿主 SDK 形状
  （`api.kv.set(namespace, key, value)`）跑规则引擎。
- `scripts/shoot-world-ui.mjs` + `frontend/src/dev-harness/worldUiVisualHarness.tsx`：
  真实 Chromium 打开验证页，8 个场景（desktop/mobile × player/devil/idle/over）截图 + 断言
  元素尺寸、可见性、控制台零错误、文档高度不溢出视口。

### 顺带修掉的两个真实 bug

- **`GameUiRenderer.renderLoopNode` 的 Fragment 缺 key** → 所有用 `for_each` 的世界包

依赖随机出杯/随机先手的断言必须**跨多局累积观测**（重开直到两种结果都出现），

## 世界包动画：能做，但有一个硬约束

用户问"是不是做不了动画"。实测（真实 iframe + Chromium `document.getAnimations()`）结论：

### 可行性

- 自定义 CSS 以 `<style>{payload.stylesheet}</style>` 内联注入（`WorldFrameRuntimeView.tsx:158`），
  iframe CSP 的 `style-src` 含 `'unsafe-inline'` → 动画可用。
- iframe 内唯一的基础表`worldFrame.css` 只有 31 行，**没有任何全局动画禁用**。
  宿主`theme.css` 里的 `animation: none !important` 只作用于主文档，不影响世界包。
- JSON 的 `style` 字段走 `CSSProperties`，所以 `animation` / `animation_delay` /
  `--自定义属性` 都能写，且值支持 `{{ }}` 模板（配合 `for_each` 的 `index_as` 可做错峰）。

### 硬约束（决定动画写法）

`GameUiRenderer` 按路径生成**稳定 key**（`${key}-${index}`），状态切换时 React 复用同一个
DOM 节点。所以：

- **循环动画**（呼吸/悬浮/跳动）：挂在常驻 class 上，照常运行。
- **一次性动画**（入场/倾倒/熄灭）：**必须靠 `class_name` 发生变化才重播**。
  实测 class A→B 动画重播（`currentTime` 归零）；class 不变则永不重播。
- 没有 JS 动画 API，不能做逐帧编排，只能靠 CSS keyframes + class 切换。

### 本次新增动画

`pf-flame`（命烛光焰，三根用 `nth-child` 错峰延迟）、`pf-devil-hover` / `pf-devil-sleep`、
`pf-poison-throb` / `pf-water-glow`（银针探明光效）、`pf-pour`（泼洒倾倒）、
`pf-btn-enter` + `pf-live-glow`（行动按钮）、`pf-text-enter`（战报）。
统一在 `prefers-reduced-motion: reduce` 块里降级，新增动画必须同步那里。

### 过程中踩到的两个坑

1. **`getAnimations()` 会误报"动画没跑"**
   浏览器会把只改 `filter` / `opacity` 的关键帧优化掉，不生成 `CSSAnimation` 对象，
   `document.getAnimations()` 直接漏掉。断言动画必须用
   `getComputedStyle(el).animationName`，否则会得出"移动端动画全挂"的错误结论。
2. **探明光效类漏了背景图**
   `pf-tube-known-poison` 一开始只写 `animation`，导致玩家看到"发光的空管"——
   银针探明了却看不出是毒药。已修（类里补 `background-image`），
   并在 `shoot-world-ui.mjs` 加了 `knownPoisonImg` 断言钉死。

### 顺带修复的 UI bug

加"刚刚倒下/泼掉"动画分支时，`when` 没有 else，兜底分支又没加 `!=` 排除，
**同一格子命中两个分支，4 格画出 5 支试管**——就是之前修过的 6 支试管 bug 复发。
已给兜底分支加 `tube.index != state.view.last_touched_index`，
并在 `poisonFeastUi.test.ts` 加了带 `last_touched_index` 的回归用例
（旧用例夹具没这个字段，undefined 永远不等于任何数字，所以漏过了）。

`logic.js` 的 view 新增 `last_touched_index`，供 UI 判断"刚刚动过的试管"。

## 牌桌布局改为"隔桌相对"

用户要求：玩家和小恶魔对着坐、玩家不需要形象、小恶魔在网页上方、
双方蜡烛统一放右侧、试管架在左侧、道具在各自前方。

### 最终布局（桌面端与移动端同一套区域划分）

`pf-table-grid` 用 grid areas 切四块：

```json
"columns": ["minmax(0, 1fr)", "auto"],
"rows": ["auto", "minmax(0, 1fr)", "auto"],
"areas": [
  ["rack", "candles"],   // 上：小恶魔头像 + 试管架
  ["mid", "candles"],    // 中：银针情报等提示
  ["seat", "candles"]    // 下：玩家道具与行动按钮
]
```

蜡烛栏 `area: candles` 跨三行，`justify-content: space-between`
把两人的命烛推到上下两端，中间留白做出"隔桌相对"的感觉。
玩家侧没有头像素材，只有"你面前的道具"文字标识。

### 小恶魔道具只暴露数量

`logic.js` 的 `buildView` 新增 `devil_item_count`，UI 显示"对面 · 手上有 N 张牌"。
**只给数量不给内容** —— 知道对手手上有几张牌是博弈信息，知道是什么就直接送死了。
（实现注意：`state.devil_items` 是 `{itemId: count}` 对象不是数组，
统计数量要用 `Object.keys(...).reduce` 而不是 `.reduce` 直接调。）

### 踩到的坑（都是真实事故）

1. **`when` 分支必须包住整个子布局**。
   重建布局时把 `pf-board` 直接放进 `pf-table.children` 而没包 `when`，
   导致进行中分支与结算分支同时渲染 —— 牌局结束后桌上还留着试管和命烛。
   已在 `shoot-world-ui.mjs` 加断言：`over` 场景 `tubeCount === 0 && candleLit === 0`。
2. **JSON 里同一个对象不能有两个 `style` 键**。
   给 `pf-chat` 加限高时多写了一个 `style`，后者静默覆盖前者，样式完全不生效。
   已加重复键检查确认两个 UI 文件都干净。
3. **移动端道具网格是 `grid` 不是 `stack`**。
   我在 CSS 写 `flex-direction: column` 想改成单列，完全无效 —— grid 不吃这个属性。
   正解是改 JSON 里的 `columns` 为单列 `1fr`。
4. **grid 行高 `minmax(0, 1fr)` 会压缩内容**。
   移动端中间行给了 `1fr`，导致情报压在试管上。改成 `auto` 让内容自适应，
   牌桌容器 `min-height: min-content` + `overflow-y: auto` 兜底。

### 大改动手法：结构化改写而不是剪裁大括号

手改 600 行的 JSONC 剪括号剪到文件损坏，最后从 `output/poison-feast-world.zip`
里恢复（zip 保存了改动前的完好版本，这是意外的好处——**每次打包都是一份快照**）。
然后改用 Python 解析 JSON 树 → 定位节点 → 替换子树 → `json.dumps` 回写。
以后改这种大 UI 文件一律走这条路，不要手工剪括号。

## 追加：两个药水动画（开局展示 + 举杯展示）

需求："开始游戏时向双方展示药水，选择自己喝/对方喝时展示药水"。

### 核心机制：CSS 动画只在 class 变化时重播

宿主 UI DSL 是纯 CSS + `when` 分支，没有计时器、没有可调用 JS。
所以"一次性动画"只能靠 **class 变化** 触发，`logic.js` 必须把
"刚刚发生了什么"编码成 view 字段。

**动画一（开局展示）** 用 `show_fresh` 布尔量而不是奇偶 class：
- `drawRound()` 里置 `show_fresh = true`，`markServe()` 里置 `false`
- UI 条件 `state.view.show_active == true`，条件 false→true 的翻转
  让元素重新挂载，动画自然重播。开局、每次换轮都触发，第一口喝/泼掉后自动退场。
- 比在 UI 里拼 `seq % 2` 可靠得多。

**动画二（举杯展示）** 必须用奇偶 class：`serve_active` 一旦为 true 就永远为真，
元素不会重新挂载。所以拆成 `pf-serve-odd` / `pf-serve-even` 两个互斥 `when` 分支，
条件是 `serve_seq % 2 == 1` / `== 0`，靠 class 名变化逼动画重播。
- 位移 `serve_dy`、倾角 `serve_lean`、光晕色 `serve_accent` 由 logic.js 算好，
  通过节点 `style` 记录以 `--pf-serve-*` 注入（`normalizeInlineStyleKey` 原样保留 `--` 前缀）
- 素材切换走 `serve_kind_code`（1 毒/ 2 清），不用字符串比较

### 两个必须记住的坑

1. **动画层必须放 `absolute` 浮层，不能是 in-flow 节点。**
   最初把两个动画层直接塞进 `pf-zone-mid` 的 children，桌面端没问题，
   移动端 `pf-zone-seat` 被挤到 **h=11px**（断言直接报错）。
   改成 `absolute`（`inset:0` + `pointer-events:none`）后脱离布局流，问题消失。
   教训：往既有 grid 区域里加东西前先问"它会不会撑高这一行"。

2. **定位用的 `transform` 会被动画关键帧的 `transform` 覆盖。**
   `.pf-serve` 用 `left/top` 钉在牌桌正中后本想加 `translate(-50%,-50%)` 居中，
   但关键帧里的 `translateY(...)` 会整个顶掉它，元素飞到左上角。
   正解是拆两段：外层只管 `left/top`，关键帧每一帧都自带 `translate(-50%, 0)` 前缀。

### 又一次手剪括号把文件改坏了

600+ 行的 `ui.desktop.jsonc`，用 Edit 替换 `pf-zone-mid` 区块时把
`"type": "stack",` 截断成了 `"ty{`，桌面端 JSON 直接解析失败、
Rust 测试报 `parse_error: expected char_literal`。
第一次修复用的 old_string 缩进和实际不符，Edit 报告成功但**没真替换**——
`node -e "JSON.parse()"` 复查才发现残留。

正确做法（和 10-11 早上那次一样的教训）：
- 改完大JSONC 立刻 `JSON.parse` 验证，别只看 Edit 的成功返回
- 需要按位置改结构时，写一次性脚本按**行号**切块替换
  （用 `lines.findIndex` 找 `"expr": "..."` 定位，再回退两行拿到节点开括号），
  临时脚本用完即删
- Read 工具显示的内容和磁盘内容可能不同步（Edit 部分成功后尤其），
  报"文件已修好"之前一定要用 Node 从磁盘读一遍确认
